# 07 — Internal Wire API (v1, frozen)

Transport for v1: **HTTP/2 + TLS (mTLS in production, optional plaintext in dev)**, JSON for control payloads, streaming bodies for shard data. The `contract` package's Go interfaces are the source of truth; this document fixes the *paths and payloads* so the three implementation streams integrate without negotiation.

A future revision swaps this transport for gRPC/protobuf + QUIC shard streams behind the same interfaces (ADR: `docs/02-architecture.md §8`). Nothing in the callers changes.

All requests carry `X-Fass-Request-Id`. Errors use `{"error":{"code":"...","message":"..."}}` with an HTTP status that mirrors the S3 error class.

---

## 1. Coordinator — `:7000`

### 1.0 Transport security

The coordinator listener is TLS in production: `--tls-cert`/`--tls-key` (env
`FASS_COORDINATOR_TLS_CERT`/`_TLS_KEY`) are required outside `--dev`, and
`--require-mtls` adds client-certificate verification against `--tls-client-ca`.
A coordinator with no certificate **refuses to start** with an actionable error
rather than serving plaintext; `--dev` (or `--dev-bootstrap`) allows a deliberate
plaintext dev listener and is reported as `insecure: true`. `/healthz`,
`/readyz` and `/v1/healthz` report the posture:

```json
{"status":"ok","schema_version":1,"tls":true,"mtls":false,"insecure":false}
```

### 1.1 Identity & authorisation
```
POST /v1/auth/keys/{access_key_id}
  → 200 {"principal":{...},"hmac_key":"<base64>","expires_at":"..."}

POST /v1/auth/authorize
  {"principal":{...},"action":"s3:PutObject","resource":{"kind":"object","bucket":"b","key":"k"},
   "conditions":{"s3:prefix":"x"}}
  → 200 {"allowed":true} | {"allowed":false,"reason":"explicit deny in policy p-123"}
```
The gateway caches `hmac_key` for ≤ 60 s and verifies signatures locally.

### 1.2 Buckets

```

### 1.3 Placement
```
POST /v1/placement
  {"shard_set_id":"...","params":{"geo_n":2,"geo_k":1,"local_n":16,"local_k":4},
   "chunk_bytes":16777216,"tenant_id":"...","project_id":"...","rc_id":"..."}
  → 200 {"shard_set_id":"...","ring_id":"...","generation":3,
         "slots":[{"geo_group":0,"local_index":0,"agent_id":"...","node_id":"...",
                   "nexus_id":"...","endpoint":"10.0.0.11:7100"}, ...]}
```
Slots are returned in shard-index order: `index = geo_group*shardsPerGroup + local_index`.

### 1.4 Objects
```
POST /v1/objects:commit        body CommitRequest → {"version_id":"...","etag":"..."}
GET  /v1/objects/{bucket}/{key}?version=  → Manifest              (404 NoSuchKey)
HEAD same                                  → Manifest headers only
DEL  /v1/objects/{bucket}/{key}?version=&bypass= → {"version_id":"...","delete_marker":true}
GET  /v1/objects?bucket=&prefix=&delimiter=&max_keys=&token=&versions=
     &key_marker=&version_id_marker=            → ListResult
                                // Version listings resume *within* a key: the pair
                                // (key_marker, version_id_marker) is the last emitted
                                // version; the next page starts strictly after it. If
                                // that version no longer exists, listing resumes at the
                                // next key (S3 semantics). NextKeyMarker /
                                // NextVersionIDMarker are returned when truncated.
```
`{key}` is path-escaped (`%2F` for slashes is accepted; raw slashes are also accepted as part of the key).

### 1.4b Bucket & object sub-resources (added 2026-10-24)
```
GET|PUT  /v1/buckets/{bucket}/acl                ACL
GET|PUT|DELETE /v1/buckets/{bucket}/lifecycle    opaque XML (gateway validates)
PATCH    /v1/buckets/{bucket}                    BucketConfig (versioning, ownership, lock, default RC)
GET|PUT|DELETE /v1/objects/{bucket}/{key}/tags?version=
GET|PUT  /v1/objects/{bucket}/{key}/retention?version=
GET|PUT  /v1/objects/{bucket}/{key}/legal-hold?version=
GET|PUT  /v1/objects/{bucket}/{key}/acl?version=
```

`version_id` is generated by the **gateway** before encryption and passed in
`CommitRequest.VersionID`; the coordinator persists it verbatim and rejects a
duplicate. This is what allows the chunk AAD to bind to the version and makes
retried commits idempotent.

#### 1.6.1 `GET /v1/repair/status`

The authoritative view of repair state for the console and `fass repair status`.
It is a read of counters maintained by the recovery service plus the current
membership snapshot — the request never scans manifests or shards.

```json
{
  "queue": {"pending": 42, "running": 3, "failed": 1},
  "oldest_pending_age_seconds": 812,
  "bytes_repaired_last_24h": 1099511627776,
  "throttled": false,
  "per_site_budget_mbps": 200,
  "last_error": "shard fetch timeout: agent 3f2a…",
  "generated_at": "2026-10-24T12:00:00Z",
  "shardsets": {"below_threshold": 17, "below_repair_watermark": 3, "unrecoverable": 0}
}
```

* **Honesty rule:** a counter the coordinator does not track is `null`, never
  `0` — the UI shows "unknown" rather than "all good". `oldest_pending_age_seconds`
  is `null` when the queue is empty; `throttled` is `null` until the repair
  scheduler has reported whether the budget is suppressing jobs;
  `per_site_budget_mbps` is `null` when no budget is configured; `shardsets` is
  `null` until the first background inventory refresh has completed.
* `queue.pending`/`queue.running` are disjoint; `queue.failed` is the number of
  failed jobs still retained for display (`POST /v1/repair/commit` with
  `"ok": false` records `last_error`).
* `bytes_repaired_last_24h` and the Prometheus series
  `fass_coordinator_repair_mttr_seconds` come from the same counters as the
  endpoint (no drift).
* `shardsets` severities are distinct and must not be conflated:
  * `below_threshold` — usable geo groups `< geo_n + floor(geo_k/2)`; this is the
    repair trigger and drives the queue.
  * `below_repair_watermark` — usable geo groups `== geo_n`; one more group loss
    makes the object unreadable.
  * `unrecoverable` — usable geo groups `< geo_n`; data loss. Must be `0` outside
    an incident and should page.
  A geo group is usable when at least `local_n` of its shards are on reachable
  agents (SUSPECT counts as reachable; OFFLINE does not).
* `generated_at` is the coordinator clock, RFC3339 UTC.

### 1.8 Dev bootstrap (`--dev-bootstrap`, dev/eval only)

`fass-coordinator --dev-bootstrap` creates (or reconciles) a deterministic
three-Nexus cluster before it starts listening, then writes the credentials and
one-time agent secrets to `<data-dir>/dev-bootstrap.json` and prints them once on
stdout:

```
FASS_DEV_BOOTSTRAP {"access_key_id":"dev-access-key","secret":"dev-secret-key",
 "region":"eu-west-1","rc_id":"dev-rc","ring_id":"dev-ring","bucket":"dev-bucket",
 "tenant_id":"dev-tenant","project_id":"dev-project",
 "agents":[{"node_id":"node-a1","nexus_id":"nexus-a","disk_id":"disk-a1-1",
            "secret":"<one-time announce secret>"}, ... 12 total]}
```

Topology: swarm `dev-swarm`; Nexuses `nexus-a/b/c`; 6 nodes (`node-a1..c2`) with
**2 disks each = 12 agents**; tenant `dev-tenant` / project `dev-project`; root
access key `dev-access-key`/`dev-secret-key`; Redundancy Class `dev-rc` =
`geo 2+1 / local 3+1`, `aag 2`, chunk 6 MiB (4 shards per Nexus on 2 nodes ⇒ one
shard loss per node leaves a group unusable, and a whole-Nexus loss leaves
`geo_n = 2` groups); ring `dev-ring` over the three Nexuses; bucket `dev-bucket`
(default RC `dev-rc`).

Semantics:

* **Idempotent.** Fixed ids; existing swarm/nexus/node/tenant/project/RC/ring/
  bucket are reused and verified (an RC with different parameters is an error,
  not a silent mutation). Re-running never changes an ACTIVE agent's
  registration: `secret` is empty for such agents (`""`), and a fresh one-time
  secret is minted only for agents that are not yet ACTIVE.
* **Disk identity is bound on first announce.** The payload's `disk_id` is the
  operator-facing slot label (`disk-a1-1`), not the agent's identity: the agent
  generates its own disk UUID and announce binds it via a node-scoped pending
  registration matched by the one-time secret. A different disk presenting an
  already-bound public key is rejected with `409 Agent with the same public key
  already exists`.
* **Activation is explicit** (`POST /v1/agents/{id}/activate`) and now refused
  with `409 AgentNotAnnounced` until the agent has announced: activating an
  unannounced agent would make it ACTIVE with no endpoint and consume the only
  legitimate announce path.
* Dev-only health timings (`--heartbeat-interval`, `--suspect-after`,
  `--offline-after`) exist so tests can observe SUSPECT/OFFLINE quickly; the
  production defaults remain 5s/15s/60s.

The 3-Nexus end-to-end test (`go test -tags=e2e ./test/e2e/`) consumes this
payload: coordinator + 12 agents + gateway as real subprocesses, S3 PUT/HEAD/GET/
list/range through `pkg/sdk`, then SIGKILL of every nexus-c agent and a GET that
must still return the original bytes from the two surviving geo groups.

## 2. Agent — `:7100`

```
PUT    /v1/shards/{shard_set_id}/{geo_group}/{local_index}
         headers: X-Fass-Params: "2,1,16,4"; X-Fass-Chunk-Index: 0;
                  X-Fass-Checksum: <uint64>; Content-Length
         body: raw shard bytes → 201 {"checksum":<uint64>,"stored":N}
GET    /v1/shards/{shard_set_id}/{geo_group}/{local_index}
         → 200 body (octet-stream), headers X-Fass-Checksum, X-Fass-Created-At
         404 {"error":{"code":"NoSuchShard"}}
DELETE /v1/shards/{shard_set_id}                 → 204 (all slots of that set)
POST   /v1/shards:has   {"ids":["..."]}          → {"present":[true,false,...]}
GET    /v1/inventory?after=<cursor>&limit=1000   → {"entries":[ShardInfo...],"next":"..."}
GET    /v1/stats                                  → {"free_bytes":..,"used_bytes":..,"shard_count":..,
                                                      "load_ewma":..,"disk_id":"..","version":".."}
GET    /v1/healthz                               → 200 {"state":"ready"}
POST   /v1/scrub                                  → 202 (kick a scrub pass)
```

Shard idempotency: writing the same `(shard_set_id, group, index)` twice with the same bytes is a no-op returning 201. Writing different bytes for the same address returns **409 Conflict** — shards are immutable.

## 3. Conventions

| Concern | Rule |
|---|---|
| IDs | UUIDv4 strings; `version_id` is a UUIDv4 (Cubbit-documented) |
| Time | RFC3339 UTC |
| Byte units | always bytes, `int64` |
| Shard addressing | `(shard_set_id, geo_group, local_index)` — never a path on disk |
| Streaming | `PutObject`/`GetObject` stream; chunk pipelines are bounded (see `docs/03 §1.3`) |
| Idempotency | placements, shard puts, repairs, and multipart part commits are all idempotent |
| Capacity errors | 507 `InsufficientStorage` from agent → gateway displaces the slot |
| Dev mode | plaintext HTTP allowed; mTLS required when `--tls` is set |
