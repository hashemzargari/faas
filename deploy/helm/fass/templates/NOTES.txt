Before this is usable:

 1. Replace every placeholder Secret name (CHANGEME-*). The chart never creates
    Secrets and never inlines certificate material. Required:
      - cluster CA public cert   (tls.caSecret, key tls.caKey; the CA *key* stays offline)
      - coordinator listener     (coordinator.tls.certSecret/keySecret)
      - gateway S3 listener      (gateway.tls.existingSecret, unless an L4/LB terminates S3 TLS)
      - gateway client identity  (gateway.mtls.existingSecret; required when tls.requireMTLS=true)
      - agent listener(s)        (agents.tls.existingSecret or per-node agents.nodes[].tlsSecret)
      - agent repair identity    (agents.tls.clientCertSecret; clientAuth EKU)
      - console listener cert    (console.tls.existingSecret; optional if a proxy terminates operator TLS)
      - console client identity  (console.coordinatorClient.existingSecret; required when tls.requireMTLS=true)
      - gateway key seed         (gateway.keySeed.existingSecret; losing it makes existing data unreadable)
      - console basic auth       (console.auth.existingSecret: console-user / console-password)
      - one announce Secret per disk (agents.nodes[].disks[].existingSecret)
      - PostgreSQL DSN           (coordinator.db.existingSecret, when dbDriver=postgres)

 2. SANs (the rule that stalls TLS rollouts): every name a peer dials must be in
    the certificate. With the default hostNetwork agents, an agent announces its
    node IP, so a shared agent cert needs every node IP as an IP SAN; per-node
    certs are cleaner. Typical generation (CA key stays on your workstation):

      fass pki init --dir ./pki/ca --cn fass-cluster-ca

      # coordinator — include service DNS names peers use
      fass pki issue-server --ca-dir ./pki/ca --dir ./pki/coordinator \
        --dns {{ $fullname }}-coordinator \
        --dns {{ $fullname }}-coordinator.{{ .Release.Namespace }}.svc \
        --dns {{ $fullname }}-coordinator.{{ .Release.Namespace }}.svc.cluster.local

      # gateway S3 edge (clients dial this name) and gateway client identity
      fass pki issue-server --ca-dir ./pki/ca --dir ./pki/gateway \
        --dns s3.example.com --ip <load-balancer-ip>
      fass pki issue-client --ca-dir ./pki/ca --dir ./pki/gateway-client \
        --identity gateway-1

      # agent on node-a1 (agent announces status.hostIP:port by default)
      fass pki issue-server --ca-dir ./pki/ca --dir ./pki/agent-node-a1 \
        --ip <node-a1-ip> --dns <node-a1-fqdn>
      fass pki issue-client --ca-dir ./pki/ca --dir ./pki/agent-client \
        --identity agent-client

      # console (optional HTTPS listener + clientAuth identity for strict mTLS)
      fass pki issue-server --ca-dir ./pki/ca --dir ./pki/console \
        --dns console.example.com --ip <console-ip>
      fass pki issue-client --ca-dir ./pki/ca --dir ./pki/console-client \
        --identity console

    Then load them into the referenced Secrets (cert+key in the same Secret for
    `tls.crt`/`tls.key`), e.g.:
      kubectl -n {{ .Release.Namespace }} create secret generic fass-coordinator-tls \
        --from-file=tls.crt=./pki/coordinator/tls.crt --from-file=tls.key=./pki/coordinator/tls.key
      kubectl -n {{ .Release.Namespace }} create secret generic fass-ca --from-file=ca.crt=./pki/ca/ca.crt
    Full runbook (rotation, mixed-mode rollout, CA-loss consequences):
    docs/08-operations.md §4 and docs/09-deployment.md §TLS.

 3. Register each disk with the coordinator and store its one-time secret. The
    node id MUST equal the Kubernetes node name (the chart passes it as
    --node-id):
      curl -sS{{ if .Values.tls.enabled }} --cacert ./pki/ca/ca.crt{{ end }} -X POST {{ $coordURL }}/v1/agents/pending \
        -H 'Content-Type: application/json' \
        -d '{"node_id":"<node-name>","disk_id":"disk0"}'
    then create the Secret from the returned "secret".

 4. Prepare the host disk directories on every agent node (owned by uid 65532):
      install -d -o 65532 -g 65532 -m 0750 /var/lib/fass/disks/disk0 ...
